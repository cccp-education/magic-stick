== Réalisé

=== Fix Cache Downloads (hors build/)

*Problème* : `build-inner.sh:27` plaçait `DL_CACHE` dans `build/cache/downloads/`.
Le `lb clean` en fin de build et `isoPurge` rasaient tout `build/`, détruisant
les tarballs/binaires téléchargés (ripgrep, fd, lazygit, opencode, VS Code, etc.)
à chaque cycle Gradle. Le build avait atteint 26GB+.

*Correctif* :
- `DL_CACHE` migré de `${BUILD_DIR}/cache/downloads` → `${PROJECT_DIR}/cache/downloads`
- `cache/downloads/` créé à la racine projet (hors `build/`)
- `cache/` ajouté au `.gitignore`
- Le cache survit à `lb clean`, `isoPurge`, `isoClean`
- Volume Docker `-v "$projDir:/magic-stick"` rend `cache/` accessible dans le conteneur

=== Fix Doublon package list

`open-infrastructure-system-config` apparaissait 2 fois dans `live.list.chroot`.
Corrigé → 1 seule entrée.

=== Tentative Rebuild ISO 0.1.15

- `isoPurge` + `isoBuild` lancé

- `~/.local/share/opencode/` (4.9GB) NON touché — données de session précieuses
- Résultat : 25GB libres (suffisant pour rebuild)

== Leçons

. Le build ISO nécessite ~30GB d'espace disque (chroot 12GB + cache 2.6GB + binary + ISO)
. Le cache downloads doit être hors `build/` pour survivre aux cycles Gradle
. `~/.gradle/caches/` peut accumuler 6.6GB+ d'anciennes versions — nettoyage périodique utile
. Ne jamais toucher `~/.local/share/opencode/` — historique de sessions précieux
