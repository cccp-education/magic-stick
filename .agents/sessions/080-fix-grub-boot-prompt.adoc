:date: 2026-06-14

== Contexte

Session 079 avait préparé la clé USB avec layout GPT 5 partitions
(bios_grub + ESP + system_a + system_b + persistence) et GRUB dual boot
Legacy+UEFI. Mais le boot physique échouait : GRUB tombait sur le prompt
`grub>` au lieu d'afficher le menu.

== Diagnostic

Deux causes racines identifiées via analyse du code et documentation GRUB :

. *core.img sans module `ext2`* — `grub-install i386-pc` par défaut n'embarque
  pas `ext2`, donc GRUB ne peut pas lire la partition ext4 `system_a` pour
  trouver son `grub.cfg`. Il tombe sur le prompt `grub>`.

. *grub.cfg force sortie série* — `terminal_output console serial` empêche
  l'affichage du menu graphique sur une machine sans port série.

== Correctifs

=== update-system.sh (3 corrections)

. `install_grub` Legacy (ligne 418-421) : ajout `--modules="biosdisk ext2
  part_gpt search search_label search_fs_uuid normal configfile echo linux
  all_video gfxterm gfxmenu font video video_fb png jpeg tga gettext"`

. `install_grub` UEFI (ligne 424-430) : ajout `--modules="ext2 part_gpt
  part_msdos fat search search_label search_fs_uuid normal configfile echo
  linux all_video gfxterm gfxmenu font video video_fb png jpeg tga gettext
  chain efi_gop efi_uga boot"` — critique pour Secure Boot où `insmod` est
  interdit

. `generate_grub_cfg` (ligne 446-480) : remplacement `serial/terminal_output
  console serial` → `gfxterm` + `insmod all_video` + `---` en fin de ligne
  kernel (conforme ISO hook 990-add-efi-support.binary)

. `verify` (ligne 813) : `LANG=C parted` pour éviter le parsing cassé en
  locale FR

. `verify` (ligne 861) : exclut partition 1 (bios_grub sans FS) du check
  labels

. `verify` (ligne 927-970) : vérifie taille `core.img` > 100 KB = modules
  embarqués (remplace `strings` qui ne fonctionne pas sur binaire compressé)

=== test-ab-partition.sh
